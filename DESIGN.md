## Overview

Dark-first SaaS landing for a passive OSINT console — Shodan ports, crt.sh subdomains, WHOIS and NVD behind one search box. *(2026-10-25: NVD joined the source strip; the old sentence named three sources.)* Before it had sections, it had a constraint: explain session-gated scanning to skeptics without a single fake number. So the hero doesn't illustrate the product — it performs it, typing `scan example.com` into a real terminal window and printing shaped sample output. Nothing glows, nothing gradients — one emerald accent on near-black does all the talking.

Then restraint became the system. Space Grotesk carries display and body, JetBrains Mono carries terminal lines, eyebrows, and monogram logos. Motion is rationed to two moments that earn it: section reveals and the typing terminal. Everything else is static and fast. The light theme exists as a full citizen, not an afterthought — same tokens, same components, verified pair by pair.

Tight sections, pill buttons, mono terminal — these aren't aesthetic picks from a gallery. They come from the job: credibility at a glance, one CTA label everywhere, scroll on. Anti-slop is the only honest design for a page that has to earn a security analyst's click.

- Density: 7/10 — Instrument panels
- Variance: 6/10 — Restrained with live layers
- Motion: 7/10 — Layered, looping, gated

- **Style:** Dark-first, Technical-mono, Restrained
- **Keywords:** saas, landing, dark-mode, mono, terminal, security, minimal-chrome
- **Era:** 2020s DevTool Marketing
- **Light/Dark:** ✓ Full (dark default, preference persisted)

## Elevation & Depth

Flat surfaces, token borders, emerald tint wash (`bg-accent/5`), mono terminal window with real scan text — depth comes from layering restraint, not shadows. No gradient surfaces, no 3-layer outer shadows on any section surface. **2026-10-12:** the elevation language gained exactly one new tool and no new shadow — an ambient **plane** behind the content (landing `GridDrift`, dashboard `ambient-layer`). Depth here means "the content is on something", not "the content floats above something".

A repo should not keep a template component whose elevation language the page forbids. Scope, so the exception cannot be read as a general licence:
  - **Landing only.** Never the dashboard, never the auth screens, never a data view — a moving row next to a result being read is a row that cannot be trusted to hold still.
  - **`transform` only.** The drift is a `translateX` on one track per row, driven by `useAnimationFrame` from a *measured* group width (`offsetWidth`), never a CSS keyframe — the distance to travel is not knowable in advance, so a fake width would drift the seam apart from the marks.

## Frontend Copywriting Rules

Mandatory for every user-facing string in the frontend. Added 2026-10-18.

1. **User-driven only.** Every piece of visible text must answer a user need: what they can do, why it matters to them, or what happens next.

2. **Essential text only.** Remove filler, marketing fluff, repetition, and explanatory paragraphs. Prefer the shortest clear version that preserves meaning.

3. **No technical language.** Do not expose implementation details, architecture, database/API terms, model names, internal states, error codes, or developer jargon in the UI.

4. **Plain, human language.** Use simple words a non-technical user understands. Avoid buzzwords and abstract claims.

5. **Action-oriented.** Buttons and links state the user's action clearly, e.g. "Save changes", "Start free trial", "Upload photo".

6. **Meaningful empty and error states.** Tell users what happened, why it matters, and the next action. Never show raw technical errors.

7. **Consistent tone.** Friendly, direct, and concise. Use sentence case for UI labels unless the product style guide says otherwise.

8. **No unnecessary onboarding text.** Explain only what users cannot infer from the interface.

### Text rules by component

- **Headlines:** Communicate the core user benefit in one short line.
- **Subheadlines:** Add only necessary context; max one sentence.
- **Buttons/CTAs:** Verb-first, specific, and short.
- **Forms:** Labels describe the input; helper text only when the requirement is not obvious.
- **Validation messages:** Say what to fix in user terms; never expose technical causes.
- **Toasts/alerts:** Confirm the outcome or next step; remove redundant words.
- **Empty states:** Explain the value of the next action and provide a clear CTA.
- **Errors:** Use a friendly message plus a recovery action; hide stack traces and internal details.

#### Numeric limits (2026-10-21, operator)

Counted per rendered string, after the copy pass that shortened the landing,
the dashboard, the demo report and the auth panel. `lib/copy-rules.test.ts`
enforces the source-copy limits; the rest is review-enforced.

| Element | Words | Sentences |
| --- | --- | --- |
| H1, H2 | 8 | 1 |
| Subhead, card description, lead | 16 | 1 |
| Body, helper, empty state, error, status | 20 | 2 |
| Source row, glossary line, tooltip | 18 | 1 |
| Button, link, label, eyebrow | 4 | 1 |
| Data-count note (`Showing 1 to 50 of 120 names`) | - | 1 |

- A paragraph never exceeds two sentences, and there is one disclosure per simulated surface (never repeated within a card).
- Numbers inside a data-count note are exempt from the word cap: the count is the sentence.
- No em dash (U+2014) anywhere under `frontend/`. Use a colon, comma or full stop; a spaced hyphen is the fallback. En dashes stay in numeric ranges (`51–100`). One U+2014 fails `lib/copy-rules.test.ts`.


### Honesty disclosures — stated once, in plain words (2026-10-18, operator)

- **One disclosure per page, never more.** A truth disclosure (`public records only`, `nothing reaches the target`, DNS-nameserver note, demo-vs-live notice) appears at most ONCE per page, in the one place it governs. Repeating it in the eyebrow, hero body, sidebar and scan card is waste, not honesty.
- **Revised 2026-10-21: one disclosure per simulated surface, never repeated inside the same card.** Two adjacent surfaces (the terminal and the preview) may each mark their own sample data, because each carries different simulated numbers. The 2026-10-18 bullet above still states the default; what changed is that the count is per simulated surface, not per page, and no card may repeat its own disclosure twice.
- **No redundant reassurance.** Lines like `Nothing is probed` / `No packets reach your target` are dropped unless the page gives the impression they contradict — a passive search page does not need to keep declaring its passivity on every card.
- **Everyday language.** Source descriptions (`NVD`, Shodan, crt.sh, WHOIS rows and cards) must read as everyday words, not as technical spec: describe what the user receives, not how the data was gathered. `severity from NVD`-style provenance jargon goes unless a rule requires it.
- **Disclosure granularity:** the page-header rule wins over longer disclosures — e.g. the hero eyebrow reads `PUBLIC RECORDS ONLY` and the DNS-nameserver note lives where the user's query is described, once.

- Existing locked decisions stand unless copy violates these rules: one CTA label per intent (`Open dashboard`), terminal preamble-style copy, `laboratory`/mono captions in the landing's technical-mono register, and `aria-label`s for icon-only controls are user-facing copy that must also comply (plain, specific).
